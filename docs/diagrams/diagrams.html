Excel upload → Databricks: what happens to a file

Everything in the first row runs locally on the uploaded file and is previewed first. Nothing is written until the toggle is on.

Plan & preview (no Databricks needed)

1Route

Filename is matched against an ordered list of regex ROUTES; first match wins → target table + write mode. Raw LMS exports are told apart by id prefix (100200_ vs 300400_).
excel_ingestion.build_plan()
→

2Reporting month

Taken from the filename (2026.07) else from the picker. The YYYYMMDD in an export name is the export date, never the period. Existing periods in the target table are shown before anything is written.
infer_reporting_month() · month_check
→

3Clean & derive

Read sheet · drop empty rows · find the email column · derive Country and Company from the email domain / company bracket · de-duplicate (key depends on the table) · tag reporting_month.
load_full_frame() · derivation.py
→

4Run-level view

Files load in dependency order (community registrations before the listings that read their Country/Job title). Duplicates across files of the same run are removed.
order_index() · prepare_run_frames()
Execute (only with “Write to Databricks” ON)

5Archive raw file

Raw file uploaded to the UC Volume (/Volumes/…/2026_07/). The app never deletes archived files; the same filename replaces its own earlier copy. Failure is recorded as archive_ok=False and logged; the table write still continues.
w.files.upload()
→

6Month replace

Once per (table, month) per run: DELETE … WHERE reporting_month = '2026.07', then insert. Re-running a month therefore replaces it instead of duplicating; other months stay untouched.
written: set[(table, month)]
→

7Insert

≤ 300 rows: batched INSERT … VALUES with escaped identifiers/literals.
> 300 rows: Parquet staged to the Volume, loaded with read_files(), staging file deleted in finally.
quote_ident() · sql_literal() · safe_stem()
→

8Record & refresh

Row counts written to .run_manifest.json so the deck service can detect new data later. Learnings tables rebuilt; Genie sources / dashboards refreshed; cached chat answers cleared.
run_manifest · refresh_all()
Shown for the synthetic organisation “Contoso”. Files that match no route are not guessed: the plan says NO MATCH and, if the contents resemble a known table shape, offers a ranked choice with a confidence score.

Five write modes, chosen by filename rule

The mode is a property of the table, not of the upload, so the same file always lands the same way.

ModeWhat it doesUsed for (demo)Row example from the demo run

Implemented as an enum plus an ordered rule list, so adding a new data source is a config change plus a test case, not new control flow (see tests/test_demo_uploads.py).

Refreshing the PowerPoint from Databricks

The deck is a template. Only shapes whose name starts with kpi: or chart: are ever touched.

1Query

Scalar KPIs and chart data come from SQL defined once in kpis.py (SCALARS, CHARTS) against the gold/bronze schemas.
run_scalar_queries() · run_chart_queries()
→

2Capture visuals

Headless browser (Playwright) opens each Lakeview dashboard once, filtered to the newest month, and screenshots the tiles listed in DASHBOARD_TILES. A tile that can't be found is a warning, not a failure.
dashboard_capture.py
→

3Fallback render

If a tile is missing, the chart is drawn locally with matplotlib from the same query result, so the deck is always complete.
chart_renderer.render_chart()
→

4Refresh template

kpi:* text boxes get formatted numbers (auto / compact / percent / text); chart:* pictures are replaced in place, fitted to the original box (or a configured override). Slides marked manual are skipped. Month labels roll forward together (2026.06→2026.07, June 2026→July 2026).
pptx_refresher.refresh_powerpoint()
→

5Summarise

Newest month is compared with the previous one straight from Databricks and written up as a plain-language “what changed” summary (KPI movement, growth, what was loaded), downloadable as Word or text.
change_summary.py

“Ask the Data”: how a question is answered

No separate LLM is bolted on. Data questions go to a Databricks Genie space that sits on the same tables; questions about the app are answered locally.

1Question

Typed in the chat page or the floating “Ask AI” widget available on every page.
→

2About the app?

Typo-corrected tokens are scored against APP_KNOWLEDGE topics (strong / weak words). A data-shaped question vetoes the local answer, so “help me count the learnings” still goes to Genie.
answer_about_app()
→

Local answer

Instant, offline, cannot invent behaviour the app doesn't have (e.g. “Archived files are never deleted”, “What tables are there?”).

3Cache

First questions only (a follow-up depends on history). Cleared after every load so figures never lag the data.
_cache_key() · clear_cache()
→

4Genie

start_conversation_and_wait (new) or create_message_and_wait (follow-up, keeps context). 240 s timeout. One automatic retry: Genie sometimes fails a question it answers on the second attempt.
databricks-sdk · w.genie
→

5Genie runs SQL

Over the bronze/gold tables, governed by Unity Catalog permissions. Result rows are fetched (first 200) so the answer shows numbers, not just prose.
→

6Answer

Text + table + an expander “SQL Genie ran” so any figure can be verified. Auth, timeout, permission and “space not found” errors become actionable messages.
Answer(text, sql, rows, error)
-- example of what the “SQL Genie ran” expander shows
SELECT Country, COUNT(*) AS members
FROM demo_catalog.bronze.analytics_teams_listing
WHERE reporting_month = '2026.07' GROUP BY Country ORDER BY members DESC
